## 追踪信息

## 需求状态与版本目标

- PRD 类型：正式推进型
- 需求来源：v0.1 真机试用与用户确认
- 证据基础：TUN 关闭时两台真机直连成功；TUN 开启时页面与信令可用但 WebRTC 失败；现有 91 项自动化通过
- 当前假设：显式本地中转可覆盖当前 TUN 故障；256 MiB 内存接收可覆盖多数 v0.2 用例
- 待确认问题：各跨系统真机组合、真实吞吐、TUN 中转实测结果
- 是否达到完整 PRD 门禁：是

版本主题：**开着 TUN 也能传，失败不靠猜，长传输不半路断。**

用户无需查 IP 命令即可让另一台电脑打开渡口；系统优先建立浏览器直连。直连失败时，只在文件字节尚未发送的前提下，由发送方选择、接收方确认，改走运行渡口服务的电脑进行本地中转。两条路径均如实显示，均不落盘。

## 方案与范围

采用“直连优先 + 显式本地中转 + 可诊断连接 + 真实进度 + 生命周期修复 + 存储预检 + 跨系统产物”。WebRTC 调优是辅助，不作为 TUN 解法。

### 本次包含

1. 展示、复制可访问 LAN 地址。
2. 直连 8 秒提示、20 秒截止；失败后可显式申请本地中转。
3. 双方确认中转、路径常驻展示、失败分类、诊断复制和保留货单重试。
4. 以接收方确认字节为准的进度、速度、用时和 ETA。
5. 等待配对 TTL 与已配对连接生命周期分离，统一心跳和有界清理。
6. 接收前存储能力与容量预检；内存模式单文件及批次总量均限制为 256 MiB。
7. Windows x64、macOS Apple Silicon/Intel、Linux x64 构建产物和验证矩阵；接收端仍为浏览器。
8. 运行服务的本机页面提供带确认的“关闭渡口”；局域网访问者不可见且不可远程调用。

### 不包含

- 文件夹、断点续传、历史、群发、设备发现、账号、公网或云端中转。
- 自动修改 VPN/TUN、防火墙或系统代理配置。
- 超过 256 MiB 的 LAN HTTP 浏览器落盘方案。
- Safari/Firefox 完整矩阵、代码签名、商店分发。

## 用户、场景与成功标准

- 目标用户：同一局域网内，在 Windows、macOS 或 Linux 电脑间临时传文件的人。
- 前置条件：一台电脑运行渡口；双方浏览器能访问其 LAN 地址；桌面稳定版 Chrome/Chromium/Edge。
- 当前替代方案：查 IP、关 TUN、聊天工具上传云端、U 盘。
- 成功标准：用户能在首页拿到可用入口；直连或经双方同意的本地中转完成逐字节一致传输；失败在 20 秒内进入可操作出口；不虚假宣称兼容性或安全性。

## 完整用户流

### 发送方

1. 启动渡口，首页看到推荐 LAN 地址、其他候选地址和复制按钮。
2. 选择文件并创建 6 位一次性接收码。未配对房间 10 分钟失效。
3. 接收方加入后，发送方批准浏览器连接；系统启动直连时间线。
4. 8 秒仍未直连时展示慢连接提示；20 秒失败后显示分类诊断、原地重试和“改用本地中转”。
5. 选择中转后等待接收方同意；接收方拒绝则回到失败出口，不发送文件字节。
6. 通道就绪后，接收方检查并接受清单；此后才传文件。
7. 传输中看到接收方已确认进度、当前/平均速度、用时和 ETA；完成或取消后释放会话。

### 接收方

1. 在浏览器打开 LAN 地址，输入 6 位码并等待发送方批准。
2. 直连成功后查看文件清单、存储模式和容量提示，接受或拒绝。
3. 若发送方申请中转，先看到路径变化、安全边界和“不落盘”说明，再允许或拒绝。
4. 接受清单后开始接收；完成后逐个保存。拒绝、取消或关闭均不自动保存。

### 跨系统

运行服务的一端下载对应系统可执行文件；另一端无需安装，只使用浏览器。README/Release 说明未签名产物在 SmartScreen、Gatekeeper 与 Linux 执行权限下的启动方式。

## 领域词汇与不变量

- 配对站：只负责房间与控制消息的 WebSocket 服务。
- 直连：WebRTC DataChannel，文件不经过渡口服务进程。
- 本地中转：双方明确同意后，文件密文帧经过本机渡口进程内存转发，不落盘。
- 确认字节：接收方已写入当前存储并回执的连续字节数；速度与完成度只以它计算。
- 业务不变量：双方批准前为零文件字节；不静默回退；不中途换路；房间码不是加密密钥；服务端不持久化清单或文件；取消/掉线/超限释放资源。

## 状态模型

房间状态：`waiting_peer → approval_pending → direct_connecting → direct_ready`；直连失败进入 `direct_failed`，可 `retrying` 或 `relay_pending → relay_connecting → relay_ready`；随后 `manifest_pending → transferring → completed`。任意活动态可进入 `cancelled`、`disconnected` 或 `failed`。

- 8 秒：仅提示“连接比平时慢”，不判失败。
- 20 秒：本轮直连终止，进入明确失败出口。
- 未配对房间：创建后 10 分钟绝对过期。
- 已配对房间：不受创建 TTL 影响；由 WebSocket 心跳、传输活动和明确断连管理。
- 不允许从 `transferring` 切换 transport；重连必须创建新一轮传输并重新确认清单。

## 功能需求

### F1 一眼就能连接

- 服务提供只读 `/api/runtime`：`version`、`port`、去重后的 `lanUrls`、`recommendedUrl`、请求方是否可关闭本机服务的 `canShutdown`。不返回房间信息。
- 终端与首页显示推荐地址并可复制。多个地址时说明它们来自不同网卡。二维码不进入 v0.2：移动端不在支持范围，桌面电脑扫码不是核心路径。
- 无 LAN 地址时仍显示 localhost，并给出防火墙/网络提示，不伪装为其他设备可访问。
- 仅当请求来自 loopback 时展示“关闭渡口”。关闭使用同源、带自定义动作头的 POST；传输中先二次警告。LAN 客户端即使构造请求也返回禁止。

### F2 直连失败后的本地中转

- 发送方仅在 `direct_failed` 且 `confirmedBytes=0` 时可发 `request_relay`。
- 接收方收到 `relay_requested` 后选择 `approve_relay` 或 `reject_relay`；同意后服务端分别签发房间、角色、单次会话绑定的高熵凭据。
- `/relay` 与 `/ws` 逻辑隔离。中转帧包括版本、会话、序号、类型和密文；服务端只校验包络、顺序与上限，不解密业务内容。
- 客户端使用随会话生成的临时密钥与带认证加密保护控制帧、清单和文件块。若受支持的加密实现不可用，中转入口禁用并明确失败，禁止明文降级。
- 威胁边界：防止被动监听和普通服务端日志看到明文；不宣称抵抗已被替换的网页、恶意渡口可执行文件或主动 HTTP 中间人，安全强度不得表述为与 WebRTC DTLS 等价。
- 服务端不落盘；每会话与全局队列设置硬上限，基于确认回执背压。取消、掉线、超限和空闲过期均清空缓冲。

### F3 可诊断连接与重试

- 时间线固定为：连接配对站、等待发送方批准、寻找局域网路线、验证通道、可以传输。
- 错误分类：`SIGNAL_OFFLINE`、`ROOM_NOT_FOUND`、`ROOM_EXPIRED`、`PEER_REJECTED`、`DIRECT_TIMEOUT`、`DIRECT_UNSAFE_ROUTE`、`RELAY_DECLINED`、`RELAY_UNAVAILABLE`、`RELAY_LIMIT`、`PEER_LEFT`。
- VPN/TUN、访客 Wi-Fi、防火墙只列为可能原因，不声称已检测。
- “复制诊断”仅包含版本、操作系统/浏览器大类、阶段与耗时、WebSocket/ICE/连接状态、候选类型和错误码；排除房间码、IP、SDP、文件名、路径和文件内容。
- 发送方重试时保留已选 `File` 对象，关闭/刷新页面后不持久化；重新生成房间与凭据。

### F4 真实速度与进度

- 接收端按连续写入字节周期性回 `transfer_ack`；发送端展示“对方已接收”，不把 `channel.send()` 入队当完成。
- UI 最多每 250 ms 更新一次；当前速度取最近 2 秒确认窗口，平均速度取全程；至少 1 秒且有正向确认后才显示 ETA，否则显示“计算中”。
- ACK 必须单调、不超过已发送字节和清单总量；异常 ACK 终止传输。
- 分块与水位优化必须由真机基线驱动，不预设提速百分比。

### F5 生命周期与资源清理

- 服务与客户端采用应用级 ping/pong；活动包括控制消息、有效 ACK 和中转帧。
- 配对成功后取消建房绝对 TTL；双方均离线、心跳超时、显式关闭或完成保留期结束后删除房间。
- 清理函数必须幂等；清空定时器、WebRTC/DataChannel、WebSocket、中转队列、临时密钥和接收缓存。

### F6 存储预检

- 清单展示前探测 OPFS 可用性；若不可用则使用内存模式。
- v0.2 内存模式硬限制：单文件不超过 256 MiB，整批总量不超过 256 MiB；零字节文件允许。
- 超限在用户接受前阻止，并指出哪个文件或总量超限。未知剩余磁盘容量时如实显示“浏览器未提供精确容量”，不做虚假保证。
- 接收方接受清单后锁定该批容量合同；传输中实际字节超过声明值立即失败并清理。

### F7 跨系统产物与验证

- 产物：Windows x64、macOS arm64、macOS x64、Linux x64；版本号和静态资源一致。
- 每个平台自动检查：可执行文件启动、`/health` 成功、`/api/runtime` 合法、首页资源完整、优雅退出。
- Chrome/Chromium/Edge 为 v0.2 基线。文件名覆盖中文、空格、emoji 和组合 Unicode。
- L3 真机矩阵：Windows↔macOS、Windows↔Linux、macOS↔Linux 三组双向直连；可用设备上至少一组 TUN 中转。缺设备写“待补证”，不得写“已支持”。

## 接口与配置

- HTTP：`GET /healthz`、`GET /api/runtime`、本机限定 `POST /api/shutdown`、静态资源。
- 信令：沿用房间消息，新增中转申请/批准/拒绝/就绪/错误和活动时间。
- 中转：独立 `/relay` WebSocket；仅接受一次性凭据与有界二进制包络。
- 配置默认值：端口 3000；未配对 TTL 600 秒；直连慢提示 8 秒；直连截止 20 秒；内存单文件/批次 256 MiB；UI 250 ms；速度窗口 2 秒。
- 无数据库、无服务器文件存储、无用户账号；重启后所有房间和凭据失效。
- 日志不得记录 IP、房间码、文件名、SDP、密钥或密文正文；只记录版本、错误码、阶段、耗时与计数。
- 回滚：关闭中转 feature flag 后仍可使用直连和诊断；协议版本不匹配时明确要求双方刷新。
